# 项目概述

按传统方式维护一台物理服务器时，操作系统、身份与数据都写在这台机器的本地磁盘上。机器损坏，系统随之停摆；更换硬件，往往要重装系统、重新配网。云原生已经让应用可以重建、迁移与滚动升级，但承载应用的物理节点仍然按这种方式维护：装机、配网、重装、换机都需要人工介入，或者为此另建一套基础设施。

Kurrent（周流）处理的就是这一层。它把系统盘从机器的本地磁盘移到存储节点上，把身份与启动凭据交给控制面在每次启动时授予。机器因此变成一个可替换的位置：换一台机器不再等于重装系统，只要把新机器绑定到原来的身份，它就能启动原来的系统。

> 身份在设备台账，系统盘在存储侧，声明在配置文件中，凭据由控制面签发；节点上只留下一次启动所需的临时连接。

## 它解决什么问题

Kubernetes 调度应用负载，但它的前提是节点已经存在、系统已经装好；它不回答「一台裸机如何成为可用节点」。Kurrent 交付承载应用的系统，位于 Kubernetes 的下一层。两者可以叠加：Kurrent 交付的系统之上可以安装 Kubernetes，由它继续编排应用；Kurrent 本身不提供启动后的应用编排。

Kurrent 也不把状态搬进另一套存储抽象。系统盘本身就是状态，它留在存储节点上；Kurrent 改变的是启动时身份与系统的来源，使「换一台机器」不再等于「重装系统」。

## 核心模型

**系统由计算身份、系统盘与启动凭据组成，归属于身份而非设备。**

为了让系统能够跟随身份流动，Kurrent 把传统上合在一台机器里的东西拆成三个对象，分别记录在不同的台账里：

| 对象 | 标识 | 含义 | 权威 |
| --- | --- | --- | --- |
| 设备（Device） | MAC | 可替换的物理位置 | 设备台账 |
| Worker | `worker_id` | 计算身份 | 控制面台账 |
| 系统盘（System Disk） | NQN | 可启动的系统本体 | 存储节点上的盘文件；归属由控制面记录 |

NQN（NVMe Qualified Name）是 NVMe 协议里标识一个存储目标的全局唯一名称，系统盘用它来寻址。

三个对象之间遵守四条不变量：

- 设备与 Worker 一对一；绑定可以变更，换绑即一次冷迁移。系统跟着 Worker 走，不跟着设备走。
- Worker 拥有系统盘；系统盘不随设备移动。设备换了，盘还在原处。
- 盘内不保存固定的机器身份；每次启动按当前绑定投影连接信息与凭据。同一块盘因此可以在不同设备上启动。
- 设备身份在 TPM 内，不随系统盘迁移；更换主板或清除 TPM 等同于更换设备。TPM 是主板上的安全芯片，设备的证明密钥在里面生成且不可导出。

设备生命周期为 `pooled → bound → revoked`：新设备先入池等待分配，绑定后成为某个 Worker 的引导节点，吊销后不再获得任何凭据。Worker 的 `readiness` 由「是否绑定设备」与「是否有系统盘」派生。一台 Worker 可以挂多块系统盘，默认盘决定菜单超时后的启动项。

## 系统由什么组成

| 角色 | 职责 | 主要组件 |
| --- | --- | --- |
| 控制面 | 身份、台账、绑定、存储调度、引导变量、审计 | 控制面服务、nginx、dnsmasq、WebUI、CLI |
| 存储节点 | 承载母盘与系统盘，导出块设备 | Agent、nvmet-host、宿主内核 nvmet |
| 设备 | 无状态算力，网络启动后成为某个 Worker 的引导节点 | 设备固件（iPXE）、系统盘内的操作系统 |

![部署拓扑：控制面、存储节点与设备之间的管理面与数据面](/diagrams/topology.svg)

控制面负责开通、身份与配置，不位于设备与存储节点之间的数据路径上。这样划分是为了隔离故障：系统启动之后，块读写直接发生在设备与存储节点之间，控制面即使宕机，也只影响新的开通与引导，不中断正在运行的系统。控制面与存储节点可以分离部署，也可以同机部署，但角色不合并。组件、端口与故障域的细节见[架构总览](../architecture/index.md)。

## 一次运行：从加电到登录

1. **网络引导**：设备开机后通过 DHCP 取得地址与下一跳服务器，再从控制面的 TFTP 服务下载经过签名的首跳程序 iPXE。控制面是该网段唯一的 DHCP 与 TFTP 提供者。
2. **身份与证明**：固件在 TPM 内创建或复用证明密钥（AK），向控制面上报设备指纹与 AK 公钥；控制面下发一个一次性随机数（nonce），设备用它对 PCR 0/2/4/7 生成 quote。PCR 是 TPM 里记录启动过程度量值的寄存器，quote 是 TPM 对这些寄存器值的签名报告，控制面据此确认启动环境没有被篡改。
3. **准入与投影**：控制面校验绑定关系、quote 签名、nonce 与平台基线，全部通过后才返回 root-path、NQN、存储节点地址与凭据；未通过的请求只能取得菜单变量，拿不到任何凭据。
4. **数据面连接**：固件用 DH-HMAC-CHAP 协议向存储节点证明「我有权连这块盘」，再以 TLS 1.3 加密连接存储节点的 `4421` 端口。
5. **系统引导**：iPXE 执行 `sanboot`，把网络盘当作本地盘，载入盘上的 GRUB 与内核。
6. **initramfs 交接**：内核启动后需要再次连接同一块盘。固件把本次连接的信息写进 NBFT 与 NBCT 两张表，initramfs 据此重新认证、建立 TLS 并挂载根文件系统。
7. **登录**：进入目标系统。此后控制面不在 I/O 路径上，其故障影响新的开通与引导，不中断已建立的连接。

任一凭据环节失败即拒绝引导，不回落明文。逐步机制与失败路径见[引导链](../concepts/boot-chain.md)。

## 能力地图

- **入池（设备）**：注册窗口开启期间，带有效 TPM AK 且开启 Secure Boot 的设备自动登记入池；无 TPM、未开启 Secure Boot 或窗口关闭时拒绝登记。
- **绑定（设备、Worker）**：设备与 Worker 一对一绑定，解绑后设备回池；已绑定的设备不会重复入池。
- **系统盘（Worker、系统盘）**：从母盘克隆系统盘，按放置策略选择存储节点，支持默认盘与多系统盘；没有默认盘时回退 `reboot`，非 4K 扇区的 GPT 盘引导时报 `0x7f22208e`。
- **引导（设备、系统盘）**：按当前绑定投影启动变量，生成菜单并完成 NBFT/NBCT 交接；证明失败的设备拿不到凭据。
- **凭据（系统盘）**：建盘时签发 DHHC-1 认证密钥，支持轮换、吊销与推送对账；吊销后拒绝引导，不回落明文。
- **运维（全局）**：检测声明漂移，记录审计与告警，支持节点排空；控制面不可用时拒绝新的开通与引导。

操作入口为 WebUI、CLI 与 REST API；命令与端点见[部署](./deployment.md)、[日常运维](./operations.md)与 [API 参考](../reference/api/)。

## 当前边界

- 引导架构为 x86_64 UEFI，网络为 IPv4；ARM 与 IPv6 尚未完成。
- 控制面为单机、文件状态，高可用未提供；控制面故障影响新的开通与引导。
- 启动后的应用编排不在本项目范围，可由上层系统承担。
- 冷迁移需要人工围栏；活迁移不支持。
- Secure Boot 首跳需按机型预置信任库，真机逐型号验收尚未完成。
- PXE 网段必须是独立信任边界，控制面是该网段唯一的 DHCP、TFTP 与引导 HTTPS 提供者。

完整边界见[路线图](../about/roadmap.md)，信任假设见[安全模型](../architecture/security.md)。

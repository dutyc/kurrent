# System Disks

A system disk is a disk file on a storage node, with the NQN as its authoritative data-plane identifier. It moves with the Worker identity, not with the physical machine: after a rebind, the new machine boots the same disk.

## Identity and Naming

```text
NQN  = <nqnBase>:<worker_id>.<os>.<os_tag>
IQN  = derived from the NQN (used by the iSCSI compatibility backend)
os_tag = 12 random hex characters (disk-level identifier)
file = <worker_id>.<os>.<os_tag>.img
```

- `os` and `os_version` are display and grouping metadata; `os` has no allowlist. A Worker holds at most one disk per `(os, os_version)`; different versions can coexist.
- `os_tag` is generated by the control plane at creation; once the disk NQN is written into boot variables, it is the disk's unique identifier.

## Sources

A disk can be cloned from a **master image** or created as a **blank disk**. Master images are never booted and are only clone sources; naming, GPT and reflink requirements are in [Master Images and System Disks](../storage/master-images.md).

## Default Disk

The default disk decides which system boots after the menu timeout:

- the first system disk becomes the default automatically; the second and later disks do not rewrite it;
- deleting the default disk promotes a remaining one if any exist, otherwise `default_disk` is cleared;
- with no default disk, `/boot-vars` returns `menu-default=reboot`, so a boot never silently enters the wrong system.

## Deletion Semantics

| Operation | Result |
| --- | --- |
| Delete a disk (`delete_file=false`) | Remove the exported target, keep the disk file; the ledger drops the disk |
| Delete a disk (`delete_file=true`) | Also delete the backing file; irreversible |
| Delete the default disk | Promote a remaining disk; clear the default when none remain |

# 身份与访问

Kurrent 里有两类完全不同的请求方：一类是人、自动化脚本与组件，它们要调用管理接口；另一类是引导链上的机器，它们要取得某次启动的凭据。这两类请求方的信任来源不同，不能混用一套凭据，因此身份体系分成两条正交的链：

- **管理面身份**：人、自动化脚本与组件如何证明自己，决定谁能调用管理接口。
- **设备身份**：引导链上的机器如何证明自己，决定谁可以取得某次引导的凭据。

两条链使用不同的信任根，不能互相替代。设备持有有效密钥不代表可以访问管理面；管理员持有证书也不代表可以冒充设备。

## 设备身份

设备身份是 TPM 2.0 的证明密钥（AK）。固件在本机 TPM 内创建受限签名密钥，私钥不可导出，因此这把密钥只能代表这台物理机器，换盘、重装都不改变它。

每次启动，设备用 AK 对 PCR 0/2/4/7 生成 quote，即 TPM 对启动度量寄存器当前值的签名报告。控制面比对平台基线，确认启动环境未被改动，并用一次性 nonce（随机数）防止重放。登记与证明的完整过程见[设备身份](./boot-chain/device-identity.md)。

## 人员与证书

管理面只经 HTTPS `443` 进入。人类用户先在本机生成私钥与 CSR（证书签名请求），控制面只接收 CSR，由 users CA 签发证书。私钥始终留在用户本机，控制面不接触。

吊销可以精确到一张证书（序列号），也可以吊销该用户的全部证书。签发与吊销流程见[人员与证书](./identity/people.md)。

## 管理 token 与会话

除客户端证书外，管理面还接受 Bearer token 与 Cookie 会话，分别服务自动化脚本与浏览器。认证器链按证书 → token → 会话顺序串行尝试，首个成功即止。

token 只存摘要，服务端不保存明文；会话只含 `{jti, exp, epoch}`，身份以服务端台账为准，删除登记即可立即失效。细节见[管理 token 与会话](./identity/tokens.md)。

## 组件身份

存储节点的 Agent 与 nvmet-host 使用 nodes CA 签发的证书。与人员证书分开签发，是为了让组件凭据只能调用组件端点，不能访问管理面。

首次加入时，组件用绑定 `agent_id` 的 bootstrap token 调 `/enroll` 换取证书。运行期按阈值 renew（到期前续期），并周期拉取 nodes CRL（证书吊销列表）；CRL 缺失或过期时 fail-closed，即宁可拒绝服务也不放行未校验的连接。加入、续期与吊销见[组件身份](./identity/components.md)。

## 审计与告警

每个管理请求写一条审计记录，包含主体类、主体、issuer、serial、fingerprint、路由、决策、原因与 request_id。写盘失败时请求返回 503——审计记不下来，请求就不放行，保证事后可追溯。

八类事件写为 `event=alarm`，可经 webhook 外投。审计字段与告警投递见[审计与告警](./identity/audit.md)。

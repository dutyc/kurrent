# 安全模型

Kurrent 的安全边界由四组彼此独立的信任组成：

| 边界 | 保护对象 | 信任锚 |
| --- | --- | --- |
| 管理面 | 谁可以调用管理接口 | users CA 证书 / 管理 token / 服务端会话 |
| 组件面 | 哪些存储节点组件可以加入与续期 | nodes CA + 绑定节点身份的 bootstrap token + CRL |
| 设备面 | 哪台机器可以取得某次引导的凭据 | TPM AK + PCR 基线 + 注册窗口 + 绑定关系；引导链另含签名首跳与固定 boot CA |
| 数据面 | 谁可以连接、内容是否加密 | DH-HMAC-CHAP + TLS 1.3 PSK |

四者不能互相替代。管理面被攻陷不等于设备可以冒领引导凭据；设备身份私钥不可导出，但仍不代表可以访问管理面。

## 威胁模型

### 前提

- 控制面宿主、存储节点宿主与网络设备由受信任的运维方管理；宿主 root 被攻陷视为对应边界的失守。
- PXE 网段是独立信任边界，且由部署方完成二层防护。
- 设备物理访问受控；能够物理接触设备并清除 TPM 或更换主板的能力不在防护范围内，其后果见「残余风险」。
- 运维人员按最小权限使用管理凭据；备份与密钥存储由部署方保护。

### 保护目标

- 未授权主体不能通过管理面读取台账、修改绑定、签发凭据或执行写操作。
- 未认领、未绑定或 TPM 证明未通过的设备不能取得其他 Worker 的引导变量。
- 已吊销的组件与用户不能继续通过 mTLS。
- NVMe/TCP 数据面内容在传输中加密；缺少凭据时拒绝引导，不回落明文。

### 残余风险

- **运行期被控**：TPM 证明只覆盖启动度量。被控的操作系统仍可在轮换窗口内取得当前 PSK，并读取已挂载的系统盘；处置手段是缩短轮换周期与吊销。
- **引导面与可用性拒绝服务**：伪 DHCP/ARP、链路中断、DHCP 池耗尽与端点资源耗尽可以阻断或干扰引导，没有完整的抗 DoS 设计。
- **平台基线验收**：独立 TPM 与 AMD fTPM 的 PCR 行为、签名固件的逐型号验收尚未完成。
- **宿主 root 与控制面单点**：控制面或存储节点宿主 root 视为对应边界失守；控制面为单节点、文件状态，宿主故障需要备份恢复。
- **物理访问**：清除 TPM 或更换主板会失去原 AK，设备退化为未注册设备，需要删除登记并在注册窗口内重新入池，原身份不复活。
- **密钥静态加密**：DHHC-1、派生 PSK 与 CA 私钥在必要位置以明文存在（见数据面），磁盘与备份加密由部署方负责。

## 管理面

### 入口收敛

- 唯一对外入口是 nginx `443`；控制面服务不监听 TCP，只监听容器内 unix socket。
- 身份头仅信任 nginx 注入；其他反代位置默认清空。若开放第二个入口或允许外部注入身份头，管理面认证即可被绕过。
- 控制面容器不挂载 `docker.sock`。

### 主体类

nginx 按证书 issuer 判定主体类：

- users CA → `human`；
- nodes CA → `component`；
- control 域不进入 443。

每个路由声明接受的主体类，未声明的路由在启动期即失败。跨类访问返回 403：组件证书不能进入管理面，人类证书不能调用组件续期。

### 凭据

| 凭据 | 保护 |
| --- | --- |
| 人员证书 | 私钥由用户本地生成与保管；控制面只签 CSR；按序列号吊销 |
| 管理 token | 台账只存摘要；scope 收窄权限；TTL 与吊销 |
| 会话 | Cookie 只含 jti/exp/epoch；身份以服务端台账为准；可逐个吊销与全部下线 |
| 管理凭据交接 | 一次性交换目录：逐文件 SHA-256、目录 0700 / 文件 0600、属主对齐；CLI 自检通过才消费并删除副本，权威文件留在状态根 |

读请求只需已认证，写请求需要 `admin` 组；会话写请求额外做同源校验。

### 审计

每个管理请求写一条审计记录；写入失败时请求返回 503（fail-closed），不允许在失去审计能力时继续执行写操作。

告警覆盖八类事件：凭据注入未通过证明、跨类访问、未知 issuer/CRL、认证失败风暴、bootstrap 身份不符、证书与 CRL 变更、用户文件变更与审计失败。

## 组件面

- 组件证书由 nodes CA 签发；首次加入需要绑定 `agent_id` 的 bootstrap token，默认一次性。
- 组件在到期前 renew；控制面校验对端证书的序列号与 CRL。
- 组件周期拉取 nodes CRL；CRL 缺失或过期时 fail-closed，不降级放行。
- 吊销组件会同时删除其 bootstrap token，堵住“吊销后立刻换发新证书”的窗口。
- 被吊销节点通过重新签发 token 与 `kurrent join` 恢复；恢复过程无需手工删除旧证书。

## 设备面

### 三个信任对象

引导准入链上有三个互不替代的信任对象：

| 对象 | 锚 | 验证时机 | 失败后果 |
| --- | --- | --- | --- |
| 首跳代码 | UEFI `db` 中的站点签名证书（平台注册窗口写入） | 固件加载 TFTP 首跳时 | 未签名或篡改的镜像不执行 |
| 引导服务器 | 签名固件内嵌的 boot CA | 4443 引导 HTTPS 握手 | 拒绝取得引导变量，无首次连接信任回落 |
| 设备身份 | TPM AK，私钥不可导出 | 每次引导的 nonce + PCR 0/2/4/7 quote | 不下发引导凭据 |

首跳把静态脚本、boot CA 与引导 HTTPS 端口一并签进二进制，控制面地址默认不写入。TFTP 只交付这个签名二进制，因此首跳内容不能被单独替换。

boot CA 只用于签发 4443 叶证书；轮换需重新签名固件，平台密钥不随 boot CA 变化。平台密钥（PK / KEK / db）由平台注册窗口在首次网络启动时写入；窗口关闭后 PK 固定，后续改动须使用离线私钥。

入池要求 Secure Boot 开启，部署不能靠关闭 Secure Boot 绕过首跳保护。

三个锚同时成立后，同二层攻击者能做的只剩拒绝服务：可以伪 DHCP/ARP 或中断链路让设备停住、反复重试，但不能替换首跳、替换脚本或冒充引导服务器。

### 设备身份与准入

- 设备身份是 TPM 2.0 的证明密钥（AK）：私钥在 TPM 内创建、不可导出，启动后的系统无法读取。
- 注册窗口只决定“是否入池”；入池要求携带有效 AK 且 Secure Boot 处于开启状态，无 TPM 或 Secure Boot 未开启的设备被拒绝。
- 绑定关系是设备侧的 `bound_worker_id`；`/boot-vars` 校验请求 MAC 是否属于该 Worker 的绑定设备。
- 挑战-证明使用一次性 nonce 与 PCR quote，nonce 原样写入 `extraData`；证明强制默认开启，无 AK、quote 无效、nonce 重放或 PCR 与基线不符一律拒绝。
- 控制面先做无副作用的 quote 结构与签名校验，再消费 nonce，最后比对基线，格式错误的 quote 不会消耗 nonce。

### 平台基线与固件变更

PCR 基线覆盖固件、Secure Boot 策略与启动配置。升级固件、修改 Secure Boot 密钥或调整启动项都会改变 PCR，证明按 `pcr_mismatch` 被拒，引导凭据停止下发。

管理员核对变更后，在设备详情中批准设备最近一次上报的摘要，设备下次启动按新基线校验。该流程把合法的平台变更与未知的度量漂移分开处理，不提供静默放行。

基线在首次证明通过时记录。首次证明若发生在攻击者控制下，基线会被污染，因此首次登记需要核对装机环境；之后的摘要变化只能走管理员审批。

## 数据面

- 认证：DH-HMAC-CHAP，target 侧按 `allowed_hosts` 限制 Host NQN。
- 加密：TLS 1.3，单端口 `4421`，固件段与内核段共用。
- PSK 由认证密钥派生，不单独存储；轮换/吊销认证密钥即原子地轮换/吊销 PSK。
- PSK 在存储节点落入内核 `.nvme` keyring；`tlshd >= 1.5.0` 与进程 keyring 优先是避免旧钥遮蔽新钥的前提。
- nvmet 后端缺少密钥或端口未就绪时，控制面不下发完整引导变量；非 nvmet 后端不投影 NVMe-oF 凭据。`menu.ipxe` 在缺少必要变量时直接失败，不拼接明文 URI。

### 静态明文边界

DHHC-1、派生 PSK 与 CA 私钥以明文形式存在于必要位置：

- 控制面状态文件（0600）；
- Agent 缓存（0600）；
- 存储节点 configfs 与内核 keyring。

Kurrent 不在应用层再加密这些位置。部署方需要负责磁盘/备份加密、宿主 root 边界与物理安全。

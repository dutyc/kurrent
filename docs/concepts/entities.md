# 设备、Worker 与系统盘

一台可以启动的计算机由三样东西组成：物理机器、运行身份、操作系统。Kurrent 把它们记录为三个独立实体：**设备**、**Worker**、**系统盘**，绑定关系再把三者组合起来。三者可以分别替换，互不牵连。

| 实体 | 标识 | 权威位置 | 含义 |
| --- | --- | --- | --- |
| 设备（Device） | MAC | 设备台账 `state/devices.yml` | 物理机器 |
| Worker | `worker_id`（主机名） | Worker 台账 `state/workers.yml` | 运行身份 |
| 系统盘（System Disk） | NQN | 存储节点上的盘文件 + Worker 台账 | 要启动的系统 |

![三实体模型：设备、Worker 与系统盘的标识、权威与绑定关系](/diagrams/zh/entities.svg)

## 一个例子

假设一台物理机器以 MAC `00:0c:29:b9:8b:2d` 登记为设备，并绑定到 Worker `worker-01`。`worker-01` 名下有一块 Ubuntu 24.04 系统盘，存放在存储节点上：

```text
设备   00:0c:29:b9:8b:2d ──绑定──► worker-01
系统盘 nqn.2026-07.com.kurrent:worker-01.ubuntu.0d26b6f33a89 ──归属──► worker-01
```

这台机器启动时，控制面按当前的绑定关系告诉它：以 `worker-01` 的身份，连接这块盘。

现在把绑定换到另一台机器上：新机器启动时拿到的仍是同一块盘、同一个身份，系统原样运行，这就是一次冷迁移。反过来，如果给 `worker-01` 换一块默认盘，机器不变，启动的系统随之改变。两种操作互不干扰，因为三个实体各自独立。

## 设备

设备代表一台物理机器。控制面以 MAC 地址为唯一键登记它，并记录硬件指纹、TPM 证明密钥的公钥、证明状态与绑定关系。

设备的生命周期有三个状态：`pooled`（在池中）、`bound`（已绑定）、`revoked`（已吊销）。

入池与绑定是两件事：入池只表示这台机器来过、控制面认识了它，不产生任何引导权限；只有管理员把它绑定到某个 Worker 之后，它才成为该 Worker 的引导节点，拿到对应的启动配置。

## Worker

Worker 是计算身份。`worker_id` 同时充当主机名，是台账与凭据的索引键。

它与设备的根本区别在于它不是机器身份：更换机器时 Worker 保持不变，系统盘与连接凭据都挂在它名下，机器只是暂时承载这个身份的硬件。

Worker 记录三类信息：绑定的设备（从设备台账投影而来）、已挂载的系统盘，以及默认启动盘。它的就绪状态（`readiness`）只取决于两个条件：有没有绑定设备、有没有系统盘。

## 系统盘

系统盘是存储节点上的一块盘文件，以 NQN（NVMe Qualified Name，NVMe 子系统的全局唯一名称）作为数据面的权威标识。

盘有两个来源：从母盘克隆，或直接创建空白盘。一个 Worker 创建的第一块盘自动成为默认盘；之后创建的盘不会自动改写默认盘，默认启动哪个系统由管理员显式指定，建盘操作不会悄悄改变启动行为。

## 绑定与放置

绑定是严格的一对一关系：一台设备只属于一个 Worker，一个 Worker 也只有一台绑定设备。绑定关系的权威记录在设备侧的 `bound_worker_id` 字段，Worker 侧只是投影。换绑只需要改设备侧这一处，两边记录不会不一致。把设备的绑定从一个 Worker 换到另一个 Worker，就是一次冷迁移。

建盘时，盘放在哪个存储节点由控制面决定，调用方不能指定。控制面先筛出合格的候选节点：必须持有这块母盘、处于启用状态且数据面就绪。再在候选中按现有盘数最少的原则均摊，避免负载集中到个别节点。

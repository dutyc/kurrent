# 路线图

路线图按技术方向组织，不按版本或日期承诺。每个方向列出已经具备的能力与仍需完成的部分；是否完成以端到端验收为准，不以代码是否合入为准。

## 方向一：NVMe-oF 协议栈与认证

**目标**：NVMe/TCP 成为唯一主数据面，认证、加密与凭据生命周期覆盖固件段与内核段。

已具备：

- 固件侧 `nvmetcp` 驱动、DH-HMAC-CHAP 认证与 NBCT 凭据接力；
- 数据面单口 4421，NVMe/TCP TLS 1.3，认证密钥派生 PSK；
- 控制面签发、推送、对账、轮换与吊销；
- 冷启动到登录提示符的整机链路验证。

仍需完成：

- iPXE 侧 NBFT 生成，替代当前验证链路的注入模拟；
- 更完整的发行版矩阵，包括 Windows 与 ESXi 的 NVMe-oF 引导；
- 更多网卡的原生驱动与固件支持矩阵扩展。

## 方向二：IPv6 与状态存储

**目标**：引导链支持 IPv6 双栈，台账与审计从单机文件平滑演进。

已具备：

- IPv4 PXE 与 NVMe/TCP 数据面；
- 单机 YAML/JSONL 状态，部署零外部依赖。

仍需完成：

- DHCP、TFTP、HTTPS 与 NVMe-oF 的 IPv6 双栈；
- 存量环境的迁移路径；
- 状态与审计入库，同时保留单机零运维的起步形态。

## 方向三：高可用与存储管理

**目标**：控制面与引导服务可冗余，存储节点可池化、可迁移、可自愈。

已具备：

- 单控制面文件状态；
- 存储节点健康探测、排空与凭据对账；
- 设备到 Worker 的换绑（冷迁移，需人工围栏）；

仍需完成：

- 控制面与引导服务的多节点冗余与故障切换；
- 存储节点冗余与故障转移；
- 盘生命周期、存储池与配置一致性的进一步收敛。

## 方向四：ARM 架构

**目标**：ARM64 设备获得与 x86 对等的无状态引导与协议栈能力。

已具备：

- x86_64 UEFI 引导链与固件产物。

仍需完成：

- ARM64 网络引导链与发行版适配；
- ARM 节点与 NVMe-oF、IPv6、认证能力的对齐。

## 当前边界

- **引导架构**：x86_64 UEFI。
- **网络**：IPv4。
- **数据面**：NVMe/TCP 为主，iSCSI 兼容后端不在主引导路径。
- **控制面**：单机，文件状态。
- **高可用**：未提供。
- **启动后编排**：不在本项目范围，可由上层系统承担。
- **固件签名**：主线未签名；Secure Boot 产物未进入主线。
- **已验证发行版**：Debian 12/13、Ubuntu 24.04/26.04、Fedora 44、AlmaLinux 10.2、openSUSE Leap 16.0。

## 进度判断

一个方向是否完成，以以下证据为准：

- 在真实硬件上完成冷启动到系统可用；
- 失败路径有明确拒绝语义，不依赖人工兜底；
- 配置、凭据与状态的所有权没有出现第二份权威；
- 回归测试覆盖新增边界，且能在变异下失败。

不以提交数量、代码行数或路线图勾选数衡量进度。
